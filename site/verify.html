VERIFIER · ZCASH MAINNET

Did these coins exist
before the incident?

Paste any Zcash transaction. Alibi reads the pool snapshot each shielded spend commits to, finds the block that snapshot comes from, and tells you whether every shielded input was already in the pool before your cut-off. Nothing else about the sender is revealed or needed.

Try:

Checkpoint for an incident

The shared anchor an alibi spend should use for a cut-off: the last 144-block grid boundary before it. Everyone proving against the same incident uses the same anchor, so the anchor does not single anyone out.

Index status

Roots are recomputed from every block, never taken from a server, and checked against two independent server operators every 144 blocks.

Use it from your own code

Same origin, no key, CORS open. Every answer is JSON.

POST /v1/verify          {"txid": "…"} or {"hex": "…", "before": "…"}
GET  /v1/checkpoint?before=…
GET  /v1/anchor/{sapling|orchard|ironwood}/{anchor}
GET  /v1/cutoff?before=…
GET  /v1/health
